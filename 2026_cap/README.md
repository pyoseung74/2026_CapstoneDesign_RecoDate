# RecoDate MVP 구현_YG_차량 이어 붙이기

이 폴더는 RecoDate MVP를 자차 경로도 구간별로 이어 붙이는 방식으로 실험하기 위한 구현 파일을 모아두는 곳이다.

이전 단계의 `API 테스트`, `추천 알고리즘 테스트`, `연구 노트`는 조사와 검증용이고, 이 폴더는 실제 MVP 백엔드/프론트엔드 구현을 위한 전용 작업 공간이다.

## 현재 구현 범위

~~현재는 FastAPI 기반 백엔드 MVP를 먼저 만든다.~~

변경:
현재는 FastAPI 기반 백엔드와 정적 HTML/CSS/JS 프론트엔드를 함께 둔다.

변경 이유:
API 문서만으로는 실제 사용 흐름을 확인하기 어렵다. MVP에서는 추천 조건 입력, 추천 결과 확인, 지도 표시, 선택한 코스의 실제 경로 계산 흐름을 화면에서 바로 확인해야 한다.

포함 기능:

- TMAP POI 통합검색으로 시작 장소 검색
- 도보/대중교통/자차 이동수단 선택
- 시작 장소와 별도로 `꼭 들를 장소`를 검색해 모든 추천 코스에 고정 포함
- `꼭 들를 장소`는 상세 설정에서 여러 개 지정 가능하며, 같은 종류는 코스 장소를 늘려서 모두 포함하고 마트·편의점 같은 잠깐 방문 장소는 기존 코스를 대체하지 않고 내부 경유지로 추가
- 상세 설정에서 선택형 숙소를 지정하면 기존 코스를 유지한 채 마지막 목적지로 추가
- 빠른 추천과 상세 설정에서 `강릉에서 숙박함`을 선택하면 저녁 식당을 추가하고, 상세 설정에서 오전 11시 이전 시작 시간을 고르면 오전 관광과 추가 액티비티를 포함한 긴 하루 코스로 확장
- 상세 설정 추천 결과에서는 자동 추천 장소별 `이 장소 변경` 버튼으로 한 곳만 검색 교체 가능하며, 시작 장소·필수 방문 장소·숙소는 교체 대상에서 제외
- 장소 교체 창의 `비슷한 장소 자동 추천` 버튼을 누르면 검색어 없이 현재 장소의 카테고리와 주변 위치를 기준으로 겹치지 않는 대체 장소를 골라 코스·예산·경로를 다시 계산
- 첫 진입 화면은 메인 대시보드이며 중앙 `RecoDate` 버튼으로 기존 코스 추천 화면에 진입
- 메인 화면에 음식점, 액티비티, 공연/관람, 관광 바로가기와 인스타 피드 형태의 추천 코스 미리보기 제공
- SQLite 사용자 DB 기반 회원가입, 로그인 상태 유지, 로그아웃, 이메일 기반 아이디 찾기 제공
- 코스 추천 화면과 추천 생성·수정·실제 경로 API는 로그인 사용자만 이용 가능
- 로그인 화면에서는 상단 탐색 메뉴를 숨기고 로그인·회원가입·아이디 찾기에 집중
- 메인 카테고리 버튼은 음식점, 액티비티, 공연/관람, 관광별 실제 강릉 장소 둘러보기 화면으로 연결
- 메인 추천 코스 미리보기 카드를 누르면 대표 장소 순서와 간략 설명을 펼쳐서 확인 가능
- 비밀번호 재설정 메일 인증과 첫 로그인 취향 온보딩은 후속 구현 범위
- 안목처럼 특수한 지역 흐름은 한 코스만 우선 추천하고 나머지는 다른 활동·마무리 장소로 분산
- 빠른 추천: 기본 3개
- 상세 설정: 최대 5개
- 음식 종류, 이동 반경, 추천 개수 반영
- 코스 구성: 출발지 → 음식점 → 카페 → 액티비티 → 마무리 산책
- 액티비티 후보: 강릉 해변, 영화관, 박물관, 미술관 중심
- 추천 카드에 교통비를 포함한 1인 기준 예상 예산 표시
- SQLite 공식 가격표 우선 반영, 미등록 장소는 카테고리 평균값으로 보완
- 안목해변처럼 지역 특성이 뚜렷한 장소는 인근 카페와 연결한 특화 순서 후보 추가
- 강릉 버스 SQLite 기반 대중교통 직행·1회 환승 탐색
- 추천 목록 단계에서는 좌표 기반 예상 거리/예상 시간 사용
- 사용자가 코스를 선택한 뒤에만 실제 도보/대중교통/자차 경로 계산
- 대중교통 모드는 가까운 구간은 도보, 긴 구간만 대중교통으로 계산
- 대중교통 모드의 긴 구간은 우선 버스·지하철 경로를 사용
- 대중교통 경로가 없는 구간만 택시 이동 필요 여부를 판단
- 대중교통 경로가 없고 택시 예상 요금이 구간당 6,000원 이하이면 해당 구간에 택시 이동을 포함
- 택시 필요 구간이 있을 때만 마지막 장소에서 출발지까지 돌아오는 비용을 계산하고, 합계가 11,000원 이하이면 귀환 포함 택시 이용 가능 범위로 표시
- 선택한 코스의 실제 경로 좌표를 TMAP 지도 SDK에 표시
- 추천 전에는 코스 흐름 보드 표시
- 추천 카드 선택 후에는 TMAP JavaScript 지도 SDK 표시
- 선택한 코스는 네이버 지도 웹 길찾기 링크로 연결 가능
- 추천 목록 단계에서는 경로 API 호출을 줄이고, 선택한 코스에서만 실제 경로 계산
- 추천 후보가 0개이면 완화 조건으로 자동 재시도

변경:
추천 목록 단계에서는 코스 흐름 보드를 유지하고, 사용자가 추천 카드를 선택한 뒤에는 TMAP JavaScript 지도 SDK를 화면 안에 표시한다.

변경 이유:
StaticMap은 이미지라 확대/이동이 되지 않는다. MVP 시연에서는 사용자가 화면 안에서 실제 지도처럼 움직이고 확인할 수 있는 SDK 방식이 더 자연스럽다.

- 추천 카드 생성 단계에서는 실제 TMAP 경로 API를 호출하지 않는다.
- 추천 카드를 선택했을 때만 `POST /api/routes/selected-course`를 호출해 실제 경로 시간을 계산한다.
- `POST /api/routes/selected-course` 응답의 `path` 좌표를 사용해 실제 경로선을 지도에 표시한다.
- 추천 카드를 선택한 뒤에만 `GET /api/maps/static`을 호출해 TMAP 지도 이미지를 가져온다.
- 추천 카드를 선택한 뒤에만 `GET /api/config/tmap-sdk`로 SDK 키를 받아 TMAP JavaScript 지도 SDK를 로드한다.
- SDK 로드에 실패하면 `GET /api/maps/static` 방식으로 대체 표시한다.
- 선택한 코스의 `전체 코스 길안내` 버튼은 네이버 API 호출이 아니라 `map.naver.com` 길찾기 URL 생성 방식이다.
- 밀집 지역에서 추천 후보가 0개이면 반경과 최소 거리 필터를 완화해 재시도한다.
- TMAP 주변 검색 카테고리 일부가 실패해도 전체 추천은 가능한 후보로 계속 진행한다.

택시 예상 요금은 강릉시 교통정보센터의 중형택시 기준을 사용한다.

- 기본운임: 2km까지 4,600원
- 거리운임: 2km 초과 6km 이하 구간은 131m당 100원
- 6km 초과 구간은 131m당 200원
- 실제 미터 요금은 교통 정체, 심야, 시외 할증 등에 따라 달라질 수 있다.

추천 카드의 예상 예산은 SQLite에 저장된 공식 가격을 먼저 반영한다.
가격이 등록되지 않은 음식점과 카페 등은 MVP 카테고리 대표값으로 보완한다.
대중교통은 강릉 시내버스 일반 성인 교통카드 요금 1,530원을 장거리 버스 이동 구간마다 반영한다.
코스 선택 후 필수 택시 구간이 확인되면 택시 예상액도 실제 경로의 교통비에 포함한다.
자차는 이동거리를 기준으로 한 연료비 근사값을 포함한다.

공식 가격표 SQLite를 다시 만들려면 백엔드 폴더에서 아래 명령을 실행한다.

```powershell

```

2026-06-01 기준 제공받은 전국 정류장 CSV에는 강릉시 행이 20개뿐이며 로컬 시내버스 노선은 포함되지 않았다.
2026-06-01 재확인 결과 TAGO 노선·정류장·도착정보 API 권한은 활성화되어 `NORMAL SERVICE`를 반환한다.
다만 TAGO 도시코드 목록 138개에 강릉시가 없고, 강릉 도시코드 노선과 강릉역 인근 정류장 조회 결과도 0건이므로 초기 DB에는 CSV 정류장만 들어 있다.
향후 TAGO에 강릉 로컬 데이터가 등록되면 위 명령을 다시 실행해 노선과 경유 정류장을 채운다.
강릉 BIS 자체 버스 데이터 제공이 필요하면 강릉시 교통과 버스정보시스템 담당자에게 별도로 문의해야 한다.

- 음식점: 15,000원
- 카페: 7,000원
- 영화관 등 실내 액티비티: 15,000원
- 박물관, 미술관 등 문화·전시: 5,000원
- 해변, 산책: 0원
- 실제 장소별 가격 데이터가 생기면 대표값을 장소별 금액으로 교체한다.

## 강릉 버스 SQLite 갱신

2026-06-01 기준 STCIS 인증키가 활성화되어 강릉 정류장과 노선별 경유 정류장을 조회할 수 있다.
강릉 BIS 공개 지도 응답은 노선별 정류장 좌표를 제공하므로, 현재 수집기는 이 좌표를 이용해 SQLite를 생성한다.

백엔드 폴더에서 아래 명령을 실행한다.

```powershell
.\.venv\Scripts\python.exe scripts\seed_bus_db.py --gangneung-bis
```

현재 DB에는 정류장 1,248개, 활성 노선 118개, 노선별 경유 정류장 5,174개가 저장되어 있다.
`운행 중단`, `운행 폐지`가 표시된 노선은 수집과 경로 탐색에서 제외한다.
