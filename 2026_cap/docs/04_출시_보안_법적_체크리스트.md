# RecoDate 출시 전 보안 및 법적 체크리스트

이 문서는 개발 점검표다. 실제 출시 전에 국내 변호사 또는 개인정보보호 담당자의 최종 검토가 필요하다.

## 도메인과 HTTPS

- 공개 웹은 `https://recodate.com`, API는 `https://api.recodate.com`으로 운영한다.
- `http://recodate.com` 접속은 HTTPS로 리다이렉트한다.
- Android 운영 빌드와 iOS 앱은 평문 HTTP를 허용하지 않는다.
- DNS 연결, 도메인 구매, TLS 인증서 발급은 별도 배포 작업이다.

## 개인정보

- 회원가입에서 아이디, 이메일, 닉네임을 수집하므로 개인정보처리방침과 이용약관을 공개한다.
- 수집 목적, 보유기간, 삭제 절차, 위탁업체, 문의처를 명시한다.
- 계정 삭제 기능과 서버 데이터 파기 절차를 출시 전에 추가한다.
- 운영에서는 웹 토큰을 브라우저 `localStorage` 대신 `Secure`, `HttpOnly`, `SameSite` 쿠키로 전환하고, 앱 토큰은 OS 보안 저장소를 사용한다.

## 외부 API

- Google Places 사진, 리뷰 수, 평점을 표시할 때 Google Maps 출처와 사진 제공자 출처를 유지한다.
- 현재 화면의 텍스트 출처 표시는 개발 확인용이다. Google Map 밖에서 Places 정보를 표시하는 카드에는 Google의 최신 가이드에 맞는 Google Maps 로고 표시를 추가한 뒤 출시한다.
- Google Places 응답은 허용 범위를 넘겨 장기 캐시하거나 별도 장소 DB로 복제하지 않는다. 장기 저장이 필요한 경우 허용되는 식별자와 최신 정책을 다시 확인한다.
- TMAP API 데이터는 약관의 저장 제한과 무료 호출 한도를 확인한다.
- 한국관광공사 관광사진은 각 사진의 출처와 이용 조건을 확인한 뒤 표시한다.
- API 키는 `.env`와 서버 비밀 저장소에만 두고, Google 키는 API 종류와 호출 출처별로 분리 제한한다.

## 스토어 심사

- Google Play Data safety 양식과 개인정보처리방침 URL을 준비한다.
- Apple App Store 개인정보 고지와 계정 삭제 흐름을 준비한다.
- 위치정보를 추가 수집하게 되면 OS 권한 안내, 처리 목적, 보유 여부를 다시 검토한다.

## 현재 남은 출시 작업

- 도메인 구매 및 DNS 연결
- HTTPS API 배포
- 계정 삭제 API와 화면
- 운영 쿠키 또는 앱 보안 저장소 기반 인증
- API 호출 제한, 로그 마스킹, 모니터링
- Google, TMAP, 한국관광공사 이용약관 최종 확인
- Google Places 카드의 Google Maps 로고 출처 표시 최종 적용
