# 프론트엔드 MVP 설명

이 문서는 RecoDate MVP 프론트엔드 화면의 역할과 API 호출 흐름을 설명한다.

## 파일 구성

| 파일명 | 역할 |
|---|---|
| `index.html` | 화면 구조. 조건 입력, 추천 결과, 지도 영역을 구성한다. |
| `styles.css` | 화면 디자인. 입력 폼, 추천 카드, 지도 레이아웃을 담당한다. |
| `app.js` | 백엔드 API 호출, 추천 카드 렌더링, 지도 표시를 담당한다. |

## API 호출 흐름

추천 버튼을 누르면 다음 API를 호출한다.

```text
POST /api/recommendations
```

이 API는 실제 TMAP 경로 API를 호출하지 않는다. 좌표 기반 예상 거리와 예상 시간으로 추천 카드만 만든다.

사용자가 추천 카드를 선택하면 다음 API를 호출한다.

```text
POST /api/routes/selected-course
```

이 API에서만 실제 TMAP 경로 API를 호출한다.

변경:
프론트엔드는 백엔드의 `/api/config/tmap-sdk`에서 TMAP JavaScript SDK용 appKey를 받아 SDK를 로드한다. 브라우저에서 지도 SDK를 쓰는 구조상 네트워크 탭에서 appKey가 보일 수 있으므로, 배포 전에는 SK open API 콘솔에서 도메인/IP 제한을 걸어야 한다.

이유:

- TMAP API 호출량을 줄이기 위함
- OpenStreetMap 타일을 여러 장 불러오면 로컬 MVP 화면에서 느려질 수 있음
- 실제 지도가 아닌데 지도처럼 보이면 사용자가 오해할 수 있음
- MVP에서는 장소 마커와 코스 흐름을 보여주는 것이 우선
- 실제 경로 시간은 선택한 코스에 대해서만 백엔드에서 계산
- appKey를 브라우저 코드에 노출하지 않기 위함
- TMAP SDK는 실제 확대/이동 가능한 지도 화면을 제공하기 때문에 StaticMap보다 MVP 시연에 적합함

## 현재 한계

- 추천 목록 단계의 지도 영역은 실제 지도 배경이 아니라 코스 흐름 보드이다.
- 선택한 코스의 지도는 TMAP JavaScript 지도 SDK로 표시한다.
- SDK 로드 실패 시에는 TMAP StaticMap 이미지로 대체 표시한다.
~~지도 위 연결선은 실제 도로 경로가 아니라 장소 좌표를 이은 선이다.~~

변경:
선택한 코스의 실제 경로 API 응답에 `path` 좌표가 있으면 TMAP JavaScript 지도 SDK의 Polyline은 이 실제 경로 좌표를 사용한다.

변경 이유:
도보 길찾기 API를 호출했는데 지도 선이 직선이면 사용자가 실제 길찾기가 반영되지 않았다고 느낄 수 있다. 실제 도보/자동차 경로 좌표를 지도에 표시해야 이동 경로가 자연스럽다.

- 실제 경로 좌표가 없는 경우에만 장소 좌표 직선 연결로 대체한다.

## 외부 길안내 연결

~~선택한 코스를 실제 지도 앱 길안내로 연결하는 기능은 없다.~~

변경:
선택한 코스의 출발지, 목적지, 경유지를 네이버 지도 길찾기 URL로 만들어 `전체 코스 길안내` 버튼을 표시한다.
버튼을 누르면 네이버 지도 웹 길찾기 화면이 새 탭으로 열린다.

변경 이유:
RecoDate 내부 추천과 실제 경로 계산은 TMAP을 유지하지만, 사용자가 실제 이동을 시작할 때는 익숙한 지도 서비스에서 바로 길안내를 확인하는 편이 자연스럽다.
이 방식은 네이버 API를 추가 호출하지 않고 URL만 생성하므로 별도 네이버 API 키가 필요 없다.

주의:

- 내부 추천, 거리 계산, 지도 표시 기준은 TMAP이다.
- 네이버 지도 링크는 최종 길안내 실행용 외부 연결이다.
- 네이버 지도 URL 형식이 바뀌면 링크 생성 함수도 수정해야 한다.
